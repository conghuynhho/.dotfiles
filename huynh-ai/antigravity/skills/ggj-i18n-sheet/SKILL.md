# GGJ i18n sheet (append + wire code)

Add new translation rows for existing code changes, then replace hardcoded Japanese UI text with `$t('key')` / equivalent.

**Source of truth:** Google Spreadsheet in the staging Drive folder. Local `resources/assetsv1/i18n/lang/**/*.json` is generated by `@ggj/build-i18n`.

**Hard rules**
- **Append only** — never update or delete existing sheet rows.
- **Japanese source** — treat hardcoded UI text as JA; translate into every language in `LANG_SUPPORT`.
- **Preview gate** — show a markdown preview table and wait for explicit user approval before any Drive write.
- **Dry-run default for tests** — if the user says dry-run / eval / don't write, stop after preview (no Sheets API write).

## When this skill applies

Trigger for: "add i18n", "i18n this diff", "hardcoded Japanese", "append to translate sheet", "wire $t for these strings", or when reviewing a PR that introduced user-facing JA strings without keys.

## Workflow

### 1. Load config + auth

From the **repo root** (look for `i18n.config.js`):

```js
// i18n.config.js fields you need
STAGING_FOLDER, TOKEN_PATH, CREDENTIAL_PATH, LANG_SUPPORT, I18N_PATH, EXCEL_PATH
```

Verify `TOKEN_PATH` and `CREDENTIAL_PATH` exist (defaults: `./build/lang/token.json`, `./build/lang/credentials.json`).

Authorize with the bundled helper (refreshes token if needed):

```bash
node <skill>/scripts/sheets-cli.js auth-check --config ./i18n.config.js
```

If auth fails, tell the user to re-run `npm run build:lang:staging` once (interactive OAuth) or refresh credentials — do not invent tokens.

Read `references/auth-and-cli.md` when wiring the CLI.

### 2. Resolve which sheet to edit

Resolve **workbook** (Drive spreadsheet) + **tab** (sheet name / JSON basename). Prefer the first hit:

1. **Comment URL** near the top of the file, e.g.  
   `// https://docs.google.com/spreadsheets/d/<SPREADSHEET_ID>/edit?gid=<GID>`  
   → spreadsheet ID + gid → tab title via Sheets API metadata.
2. **Import path** like `import … from '@/i18n/lang/desktop/sell-input.json'`  
   → workbook namespace `desktop`, tab `sell-input`.
3. **Staging folder + namespace** — list spreadsheets under `STAGING_FOLDER`, match workbook name (`desktop`, `common`, `components_desktop`, …). Tab from map-index / import / user hint.
4. Ask the user if still ambiguous.

Use:

```bash
node <skill>/scripts/sheets-cli.js resolve \
  --config ./i18n.config.js \
  --url "https://docs.google.com/spreadsheets/d/.../edit?gid=..." \
  # or --workbook desktop --tab sell-input
```

Details: `references/resolve-sheet.md`.

### 3. Identify column format

Read row 1 of the target tab. Expected layout (order may vary; match by header name):

| index | ja | en | th | zh | tw | vi | hk | … |

- Column A = key (`index`)
- Language columns = codes from `LANG_SUPPORT` (`ja,en,th,zh,tw,vi,hk`)
- Sheet 1 of the workbook is often `map-index` — **do not append translation rows there**
- Cell `J2` (REF_CELL) may list common reference keys — leave it alone unless the user asks

Confirm headers with:

```bash
node <skill>/scripts/sheets-cli.js headers \
  --config ./i18n.config.js \
  --spreadsheet-id <ID> --tab sell-input
```

Full layout notes: `references/sheet-format.md`.

### 4. Collect hardcoded strings

From **git changes** and/or **mentioned files**:

```bash
git diff --unified=0   # or git diff main...HEAD / user-specified range
```

Extract user-facing string literals (templates, JS/Vue/TS). **Include** Japanese UI copy and obvious labels/messages. **Skip**:

- Already `this.$t(...)`, `$t(...)`, `i18n.t(...)`, `t(...)` with existing keys
- URLs, paths, class names, event names, API field names, pure numbers, debug logs
- Comments (unless the user asked to i18n comment-only copy — rare)

Deduplicate by exact JA text. Optionally check whether that JA string already exists in the tab (read values); if it does, **reuse the existing key** in code — do **not** append a duplicate row.

### 5. Keys + translations

- **Keys:** short semantic kebab-case English (`add-currency`, `fail-des`, `try-again`). Prefer ≤3 segments, ≤24 chars when readable. Avoid pure numeric IDs unless the sheet is overwhelmingly numeric and the user insists.
- Ensure key uniqueness against existing column A values.
- **Translations:** JA = source text; fill every `LANG_SUPPORT` language. Keep HTML fragments intact when present. Match tone of nearby rows in the same tab when possible.

### 6. Preview (required)

Show the user a table before any write:

| key | ja | en | th | zh | tw | vi | hk | code locus |
|-----|----|----|----|----|----|----|----|------------|

Also list planned code replacements (`"日本語"` → `this.$t('short-key')`).

Ask: **Approve append to Google Sheet?** Stop until they say yes (or request edits).

### 7. Append rows (after approval)

Never use update/clear/batchUpdate that overwrites cells. Append only:

```bash
node <skill>/scripts/sheets-cli.js append \
  --config ./i18n.config.js \
  --spreadsheet-id <ID> \
  --tab sell-input \
  --rows-json ./i18n-append-rows.json
```

`rows-json` is an array of objects `{ "index": "short-key", "ja": "...", "en": "...", ... }` — the CLI maps headers and appends one row per object at the end of the tab.

If the user requested dry-run, skip this step and say so clearly.

### 8. Replace code + keep local JSON usable

1. Replace each approved hardcoded string with `this.$t('key')` / `$t('key')` / template binding consistent with the file.
2. Ensure the component already imports and registers the lang JSON (`i18n: { messages: i18n }` pattern used in this repo). Add the import only if missing.
3. Patch the matching local JSON under `I18N_PATH/<workbook>/<tab>.json` for all languages so `$t` works before the next full lang build. Sheet remains source of truth; remind:

```bash
npm run build:lang:staging
```

when they want a clean regenerate from Drive.

### 9. Report

Summarize: spreadsheet URL + tab, keys appended (or dry-run), files edited, reminder not to hand-edit old sheet rows, and that rebuild syncs JSON from Drive.

## Key naming examples

| JA (source) | key |
|-------------|-----|
| 計測通貨ペアを追加 | `add-currency` |
| 再度お試し下さい。 | `try-again` |
| ファイルのアップロードに失敗しました。 | `upload-fail` |

## Out of scope

- Creating a brand-new workbook/tab (ask user; map-index updates are manual/product process)
- Editing production backup folders (`BK_FOLDER_ID`) — always staging
- Deleting or rewriting existing translations
